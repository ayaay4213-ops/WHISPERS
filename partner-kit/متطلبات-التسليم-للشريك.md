# Whispers — ملف التسليم للشريك التقني

## الهدف
تسليم مشروع عربي RTL بهوية أرجوانية داكنة وذهبية، قابل للتجربة من الهاتف، مع توضيح الفرق بين ما هو موجود في النموذج الحالي وما يجب أن ينجزه الشريك قبل الإطلاق. هذا الملف لا يدّعي أن التكاملات الخارجية تمت.

## التقنية الحالية التي تم التحقق منها
- واجهة ويب/PWA: HTML وCSS وJavaScript Modules.
- ملفات التشغيل: `index.html` و`js/app.js` و`js/api.js`.
- عامل API موجود في `workers/hamsat-api.js` يعتمد على جلسة Puter وKV.
- ليست نسخة Flutter أصلية حاليًا.
- رابط API المكتوب في `js/api.js` يجب التحقق من ملكيته ونشره وصلاحياته قبل الاعتماد عليه.

## الحالة الحالية
| الوحدة | الموجود الآن | المطلوب قبل اعتبارها جاهزة |
|---|---|---|
| الهوية والواجهة | واجهات عربية وهوية بصرية | اختبار الهاتف وإتاحة الاستخدام |
| الحسابات | تسجيل Puter تجريبي؛ البريد/الهاتف مجرد واجهة | مزود حسابات فعلي، تحقق البريد/الهاتف، استعادة الحساب، حماية الجلسات |
| الملف الشخصي | نموذج حفظ عبر API | اختبار قاعدة البيانات والتحقق من المدخلات والصور والمعرّفات الفريدة |
| الغرف | قائمة وإنشاء/حذف عبر API | صلاحيات المالك والمشرف، الحضور اللحظي، حدود الغرفة |
| الصوت المباشر | غير منفذ | مزود WebRTC مثل LiveKit أو Agora، إصدار رموز من الخادم، اختبار الشبكات والأذونات |
| الدردشة داخل الغرفة | يلزم فحص/استكمال التكامل | تخزين وبث لحظي ومكافحة الإساءة |
| الهدايا | كتالوج فقط | إرسال فعلي، معاملات ذرية، منع الرصيد السالب، سجل تدقيق |
| المحفظة | رصيد ومكافأة تجريبية حسب API | دفتر قيود مالي على الخادم، idempotency، تسوية ومراجعة |
| الرسائل الخاصة | غير مكتملة | محادثات وصلاحيات وحفظ وتحديث لحظي وإبلاغ/حظر |
| المتابعة/المفضلة | غير مكتملة | جداول وعلاقات وواجهات API |
| الإشعارات | غير مكتملة | إشعارات داخلية ثم Push بعد اختيار المزود |
| الوكالات والمضيفون | غير منفذة بالكامل | أدوار وموافقات وقواعد مكافآت وتقارير |
| السحب المالي | غير منفذ | مراجعة قانونية ومزود دفع متاح للبلدان المستهدفة وإجراءات KYC عند اللزوم |
| الإدارة | لا توجد لوحة إنتاج محمية مكتملة | RBAC، سجل تدقيق، إجراءات مراجعة وحظر |
| رابط عام | يحتاج استضافة موثقة | نشر HTTPS واختبار رابط من هاتف آخر وحساب تجريبي |
| Android | لا توجد حزمة إنتاج مؤكدة | قرار PWA أو بناء Android بعد الاختبار والتوقيع |

## قرارات لازمة قبل الربط
1. اعتماد منصة الخلفية ومالك حسابها (لا تُرسل كلمات المرور داخل المحادثات).
2. اختيار مزود الصوت والبلدان المستهدفة وعدد المستخدمين المتوقع.
3. تحديد ما إذا كانت العملات افتراضية فقط أم ستتصل بدفع حقيقي.
4. تحديد سياسة الخصوصية، شروط الاستخدام، العمر الأدنى، البلاغات والاحتفاظ بالبيانات.
5. تعيين مسؤول يملك الاستضافة والنطاق ومفاتيح الخدمات.

## شروط قبول التسليم
- إنشاء حساب، تسجيل دخول وخروج، واستعادة حساب حقيقي.
- فتح رابط HTTPS من جهاز آخر دون صلاحيات المطور.
- تجربة مستخدمين اثنين في غرفة واحدة وسماع الصوت في الاتجاهين، مع الكتم وإيقاف الميكروفون.
- إرسال هدية بين حسابين وتطابق الرصيد وسجل المعاملة بعد إعادة تسجيل الدخول.
- منع إرسال هدية برصيد غير كافٍ، ومنع خصم العملية مرتين عند إعادة الطلب.
- اختبار الرسائل الخاصة، الحظر، الإبلاغ وصلاحيات المشرف.
- لا يستطيع المستخدم العادي الوصول إلى لوحة الإدارة أو تعديل أرصدة الآخرين.
- نسخة احتياطية، مراقبة أخطاء، سياسة خصوصية وشروط استخدام.
- لا تُعرض أرصدة تجريبية أو أرباح تقديرية على أنها أموال حقيقية.

## أمان لا يمكن تجاوزه
- لا تضع مفاتيح سرية في ملفات JavaScript العامة.
- لا تسمح للعميل بتحديد سعر الهدية أو تعديل الرصيد مباشرة.
- كل تغييرات الرصيد تتم على الخادم في معاملة ذرية مع سجل غير قابل للتعديل العادي.
- إصدار رموز الصوت يتم من الخادم بعد التحقق من العضوية والصلاحيات.
- كل نقطة API تتحقق من هوية المستخدم وملكيته للموارد وصلاحياته.
- استخدم بيانات تجريبية فقط في العرض للمستثمر.
